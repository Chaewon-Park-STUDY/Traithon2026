# PREREG d28: α를 바꿀 때 사람 검토량과 사람이 못 보는 놓침의 변화

작성일: 2026-11-08 (코드 실행 전). 근거: 강의 6.4.2(감독과 개입의 구분), 6.3.2(automation bias), 4.4.4(RACI). 레포: d6_calibrate.py, d7_evaluate.py, common.py(POLICY).

## 질문
conformal의 α(허용 오류율)를 현행 0.05에서 바꾸면, (1) 사람이 검토해야 하는 기사 수와 (2) 자동 통과되어 사람이 못 보는 클릭베이트 수가 어떻게 달라지는가.

## 방법 (실행 전 고정)
1. d6(--maxq)와 d7의 계산을 같은 규칙으로 재현한다. qhat은 k=ceil((n+1)(1-α)), q=sorted[min(k,n)-1], k>n이면 1.0.
2. q_클릭베이트 = max(calib 클릭베이트의 q, calib_auto_check의 q), q_정상 = calib 정상의 q.
3. 기존 calibration_*.json, test_decisions_*.csv는 읽기만 하고 덮어쓰지 않는다. 출력은 d28_out/ 아래에만 쓴다.
4. 재현 확인: α=0.05에서 기존 test_decisions의 set과 test 행 단위로 비교한다. 불일치가 1건이라도 있으면 이 분석의 숫자는 쓰지 않는다.
5. 대상: subset=="test" 중 정치·경제를 제외한 기사(민감 기사는 α와 무관하게 전량 사람이 봄).
6. 지표(비민감 test, 클래스 조건부): fc, pn, 정상 중 판정 유보, tp, 클릭베이트 중 판정 유보, miss. miss는 Clopper-Pearson 95% 구간.
7. 기사 1,000건당 환산(클릭베이트 비율 π 가정): 검토 건수=1000*((1-π)(fc+정상 판정 유보)+π(tp+클릭베이트 판정 유보)), 자동 통과 건수, 사람이 못 보는 클릭베이트 건수=1000*π*miss(구간 포함), 자동 통과 안의 클릭베이트 비율.

## 표시용 격자 (선택한 값이 아니며 결정 기준도 아님)
- α: 0.01, 0.02, 0.03, 0.05, 0.075, 0.10, 0.15, 0.20, 0.30
- π: 0.05, 0.10, 0.25 (실제 유입 비율은 모른다. 모를 때는 격자를 그대로 보여준다)

## 해석 규칙
- 이 분석은 test 한 번의 표본이며, α별 miss의 구간이 넓으면 α끼리의 차이를 해석하지 않는다.
- 검토자가 정확하다는 가정(h=0)의 값이다. 실제 사람의 독립 오류는 측정하지 않았다.
- 검토 건수는 동일한 AI 점수를 쓰는 값이라 사람의 실제 검토 시간으로 환산하지 않는다.
- calib 표본이 작아 qhat이 1.0이 되는 α(작은 α)에서는 전부 검토 대상이 되는 현상이 나올 수 있다. 이는 결과가 아니라 표본 한계로 적는다.
- 최적 α를 정하지 않는다. 팀이 정할 정책 선택의 입력 자료로만 쓴다.
- 공개 시 숫자는 멘토 확인 후 사용한다. AI-Hub 행 단위 데이터는 레포에 올리지 않고 집계 CSV만 올린다.
