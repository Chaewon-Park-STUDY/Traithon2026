# PREREG d31: 단계형 검토와 피드백 루프의 비용 (L0~L4)

작성일: 2026-11-08 (코드 실행 전). 근거: 강의 6.4.2(감독과 개입의 구분), 6.3.2(automation bias), 4.4.4(RACI). 레포: d28_alpha_sweep.py(재사용), d26_audit_design.py(감사 검정), common.POLICY, docs/BK01 §Agent 자율범위, docs/BK02 RISK-04·RISK-03, docs/BK03 검토 인력 산정식.

## 질문
(1) 같은 검토량으로 놓침을 더 줄이는 단계(L2)가 α 변경보다 나은가. (2) 감사(L4)는 놓침이 늘었을 때 얼마나 늦게 알아채고, 그동안 얼마나 새어 나가는가. (3) 놓침 1건의 비용이 검토 1건 비용의 몇 배 이상일 때 어떤 설계가 싸지는가.

## 단계 정의 (설계)
- L0: 정치·경제 기사는 α와 무관하게 전량 사람이 본다. 근거는 BK02 RISK-04(정치·경제적으로 민감한 주제에서 모델 편향 판단, 기본권 우선 적용, 자동판정 중지 후 인간 검토 이관)이다. BK03은 "정치·경제 등"으로 열어 두었으나 다른 카테고리를 넣을 근거는 아직 정해지지 않았다. 이 분석의 per-1000 수치에서는 제외하며(d28과 동일), 카테고리를 추가하면 비민감 분모가 바뀌므로 별도 민감도 분석으로 다룬다.
- L1: 현행 conformal 판정(d6 --maxq, d7)으로 나눈다. 확정 후보=예측 집합이 {클릭베이트}뿐(BK01: 사전 승인 필요, 검토자 확인 후 게시 보류·경고), 자동 통과=집합이 {정상}뿐(사람이 보지 않음), 판정 유보=집합이 둘 다 포함하거나 둘 다 비어 있음(사람에게 이관). 자동 통과는 "보류·경고 조치를 하지 않고 그대로 두는 것"을 뜻하며 게시 행위를 에이전트가 실행하는 것이 아니다(BK04 "게시·반려 실행은 항상 사람이 결정"과의 정합을 위한 정의이며, BaseKit에서도 명시가 필요하다).
- L2: 자동 통과 기사를 p_cb 높은 순으로 위에서 x%(자동 통과의 π 가중 비율) 추가 검토한다. 이번 분석은 점수 순위만으로 시뮬레이션한다(두 번째 AI 점검은 GPU 이후, 이 분석 범위 밖).
- L3: 사람이 검토한다(검토자 정확 가정, h=0). 이 분석은 검토자 수를 모델링하지 않고 기사 1,000건당 검토 건수(이관율)만 센다. 필요 검토 인력은 BK03의 산정식 (일일 기사 수 × 이관율) ÷ (1인 일일 처리 건수)로 계산하며, 일일 기사 수와 1인 처리 건수는 서비스 적용 조직의 입력 가정이고 이 분석이 정하지 않는다. 전체 이관율=s+(1-s)×(비민감 이관율), s는 민감 기사 비중으로 실제 트래픽의 값을 모르므로 숫자를 정하지 않는다.
- L4: 자동 통과 표본을 사후 감사하고 d26의 정의 B 검정(단측 exact binomial, δ=common.POLICY)으로 경보를 낸다.
- 피드백 루프(설계만 정의하고 이번 분석에서는 효과를 측정하지 않음): 경보 1단계=감사율 상향, 2단계=α 조정 또는 감사에서 얻은 라벨로 재보정, 3단계=자동 통과 중지(전량 사람).

## 방법 (실행 전 고정)
1. d28과 같은 규칙으로 α별 임계값을 구한다(thresholds, route 재사용). 재현 확인: x=0일 때 검토 건수와 못 보는 놓침이 d28 결과 CSV와 일치해야 한다(일치하지 않으면 숫자 사용 안 함).
2. 부분 1 (L2): 대상은 subset=="test" 비민감 기사. 자동 통과(set=normal) 기사를 p_cb 내림차순으로 정렬하고, π 가중(정상 기사 가중 (1-π)/정상 수, 놓친 클릭베이트 가중 π/클릭베이트 수) 누적이 자동 통과 가중 합계의 x가 될 때까지 추가 검토한다. 지표는 기사 1,000건당 검토 건수와 못 보는 놓침. 불확실성은 test를 클래스별로 층화 bootstrap(B=2000, SEED=20261109)한 백분위 95% 구간이며 보정 표본은 고정한다(보정 불확실성은 포함하지 않음). 동점은 입력 순서를 유지한다.
3. 부분 2 (L4 경보 지연): 감사는 d26과 같은 검정. 귀무 κ0=κ(α), 대립 κ1=κ(배수×α) with κ(m)=π·m/(π·m+(1-π)·pn), pn은 test에서 구한 P(자동 통과|정상). 감사 묶음 크기 B_a마다 검정하고 경보 확률 q=P(경보|묶음)을 정확 이항으로 계산한다. 경보까지 기대 묶음 수=1/q, 감사된 기사 수=B_a/q, 감사율 f_a에서 자동 통과 처리량=감사된 기사 수/f_a, 새어 나간 클릭베이트(감사되지 않은 자동 통과 안)≈κ1·감사된 기사 수·(1-f_a)/f_a. 배수=1은 거짓 경보 확률(size)을 의미한다.
4. 부분 3 (비용 기준선): 비용=검토 건수+ρ×못 보는 놓침(ρ=놓침 1건 비용/검토 1건 비용). ρ는 표시용 격자이며 값을 정하지 않는다. 각 π, ρ에서 격자 안 가장 싼 설정과 현행(α=0.05, x=0)의 비용을 비교하고, bootstrap에서 그 설정이 가장 싼 설정으로 뽑힌 비율을 함께 보고한다.

## 표시용 격자 (선택한 값이 아니며 결정 기준도 아님)
- α: d28과 동일 [0.01, 0.02, 0.03, 0.05, 0.075, 0.10, 0.15, 0.20, 0.30]. π: [0.05, 0.10, 0.25].
- x: [0, 0.01, 0.05, 0.10, 0.20, 0.50]. 배수: [1, 1.5, 2, 3]. 감사 묶음 B_a: [203, 500, 1000, 3000] (203은 기획본 값, 근거 미확인). f_a: [0.02, 0.05, 0.10]. ρ: [1, 3, 10, 30, 100, 300, 1000].

## 해석 규칙
- 이 분석은 설계 비교이며 최적 설정을 고르지 않는다. 격자 안의 비교로만 읽는다.
- 비용 비율 ρ와 놓침 증가(배수)는 가정이다. 되돌림 비용과 지연 비용은 측정하지 않았다.
- 부분 2의 κ0는 π와 pn을 안다고 가정한다. 실제 운영에서 π는 모르는 값이다(d26의 한계를 그대로 가짐).
- L2는 점수 순위가 자동 통과 안의 놓침을 찾아낸다는 가정이 아니라, 이 test에서 실제 순위가 그런지를 본 것이다. test는 쉬운 편일 수 있어(d27) 운영에서 같은 이득이 나온다는 보장이 없다.
- 사람 검토자가 정확하다는 가정(h=0)이다. BK02는 정확성을 "정답은 사람의 최종 판단"으로 정의하므로 이 정의 아래에서는 검토자 오류와 AI 추종(automation bias)을 측정할 수 없다. 이 분석의 정답은 데이터셋 라벨이며, 두 정의의 차이는 BaseKit 수정에서 다룰 사항이다.
- 공개 시 숫자는 멘토 확인 후 사용한다. 출력은 집계뿐이며 AI-Hub 행 단위 데이터는 올리지 않는다.
