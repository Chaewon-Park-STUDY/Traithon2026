## 2-1. GPU 사용 안내 (운영팀 공지, 10/30)

운영팀은 모델 파인튜닝을 계획하는 팀에게 GPU를 지원합니다. 다만 현재 모델로 테스트 데이터셋 검증을 먼저 마친 팀 중 준비가 된 팀에 한해 제공됩니다.

신청 순서는 다음과 같습니다.
1. 현재 모델로 테스트 데이터셋 검증을 진행합니다.
2. 테스트 결과 또는 검증 완료 화면을 준비합니다.
3. 디스코드 팀방에서 담당 멘토에게 결과를 공유하고 GPU 사용을 요청합니다. 검증 결과를 확인한 뒤 지원합니다.

우리 팀에 적용하면 다음과 같습니다.
- 예선 설계는 모델을 바꾸지 않고 A.X 4.0 Light의 라벨 확률에 conformal 보정을 얹는 방식입니다. 이 설계로는 파인튜닝이 필수가 아닙니다.
- 랩업은 데이터 추가, 파인튜닝, 모델 변경을 선택한다면 기존 방식의 어떤 한계가 확인되었고, 그 방법이 무엇을 보완하며, 적용 후 무엇이 달라졌는지를 연결해서 설명하라고 했습니다.
- 그래서 먼저 현재 모델로 검증을 하고, 그 결과에서 한계가 확인될 때만 파인튜닝을 선택하는 순서로 진행합니다.

파인튜닝 여부 판단 기준(제안)은 다음과 같습니다.

| 검증에서 확인되는 상황 | 판단 |
|---|---|
| 라벨 확률이 심하게 보정되지 않았고 이관율이 검토 용량을 크게 넘음 | 파인튜닝 후보. 한계, 보완 목적, 적용 후 변화를 기록하고 GPU 요청 |
| 이관율과 미탐 비율이 기준 안에 들어옴 | 파인튜닝 없이 진행. 보정 설계로 신뢰성을 설명 |
| 정치·경제 슬라이스 오탐률만 두드러지게 나쁨 | 슬라이스 보정이나 데이터 보강을 먼저 검토하고, 부족하면 파인튜닝 |
| 실행환경 문제로 검증 자체가 느리거나 불가능 | GPU 요청 전에 멘토에게 먼저 사정 설명 |

멘토에게 확인할 점은 두 가지입니다. 파인튜닝 없이 검증만 하는 팀도 검증용 GPU를 받을 수 있는지, 그리고 현재 모델과 테스트 데이터셋이 팀마다 정해진 것인지 우리가 고른 것인지입니다.

## 3. 구현 범위 (제안)

남은 기간은 약 3주입니다. 아래 구분은 제안이며 팀 논의로 확정합니다.

| 구분 | 내용 | 이유 |
|---|---|---|
| 반드시 | 현재 모델로 테스트 데이터셋 검증과 결과 화면 캡처 | GPU 요청 조건이며 이후 작업의 출발점 |
| 반드시 | 라벨 확률 추출, class-conditional conformal 보정, 자동 통과 구간의 미탐 비율 확인 | 핵심 영향 IMPACT-01의 근거 |
| 반드시 | 이관율과 검토 용량 비교 | 핵심 영향 IMPACT-03의 근거 |
| 반드시 | 정치·경제 슬라이스별 오탐률 보고 | RISK-04 근거 |
| 가능하면 | Auto/Direct 분리 평가, 가중 보정 민감도 점검 | RISK-13, robustness |
| 가능하면 | 프롬프트 인젝션 케이스 확인 | RISK-08 |
| 여유가 있으면 | 대시보드 시연 화면 | 멘토 확인 후 결정 |
