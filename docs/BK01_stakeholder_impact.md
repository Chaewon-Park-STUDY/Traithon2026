## 0. 문제 정의 (클릭베이트 탐지보다 먼저)

> 멘토링 지적: "클릭베이트가 무엇인가"가 아니라 "누구의 어떤 어려움을 해결하는가"를 먼저 정의해야 함.

| 요소 | 내용 |
|---|---|
| 누가 | 뉴스 콘텐츠를 소비하는 독자, 특히 투자 판단처럼 의사결정에 기사 내용을 활용하는 사람 |
| 어떤 상황에서 | 포털·뉴스 플랫폼에서 기사를 접할 때, 제목만으로 1차 판단을 내리는 순간 |
| 어떤 어려움을 겪는가 | 제목이 본문 내용을 과장·왜곡해 불필요하게 클릭하거나, 잘못된 인상(예: 근거 없는 공포·기대)을 갖게 됨 |
| 우리는 어떻게 해결하려는가 | 게시 전/직후 단계에서 제목-본문 불일치를 탐지해 운영팀(검토자)에게 알리고, 필요한 경우 경고 표시·보류 조치로 독자가 왜곡된 정보를 그대로 소비하지 않도록 함 |

→ 즉 본 서비스는 "클릭베이트를 탐지하는 AI"가 아니라, **"독자가 왜곡된 정보로 불필요한 판단을 내리지 않도록 게시 단계에서 미리 걸러주는 서비스"**로 정의한다. 클릭베이트 탐지 Agent는 이 문제를 해결하는 핵심 수단이다.

**대표 사례 (실제 보도 비교, 기관·언론사명 비공개)**: 대학 비대면 시험의 부정행위 의혹을 다룬 동일 사건 보도 3건을 비교했을 때, 세 제목 모두 학생 커뮤니티 익명 투표의 "커닝했다" 응답 수(수백 명대)를 확정된 부정행위자 수처럼 제시하거나 AI 사용을 사실로 단정했다. 그러나 본문은 "실제 인원은 확인되지 않았다", "AI 사용은 학생 증언에 근거한 추정"이라고 밝히고 있었다. 즉 독자가 제목만 읽으면 본문이 말하는 것보다 훨씬 강한 사실로 받아들이게 된다. 이것이 본 서비스가 줄이려는 문제의 구체적 모습이다. (※ 본 서비스는 위와 같은 제목-본문 일치성만 판단하며, 본문 사실 여부는 §1(5)에 따라 판단하지 않는다.)

## 1. 서비스 정의

### (1) 서비스 정체성 (전체 시스템 vs 개별 기능)

본 서비스는 **클릭베이트 탐지 단독 서비스가 아니라, "뉴스 콘텐츠 신뢰성 수호 멀티에이전트 시스템"(가칭)의 일부**로 정의한다. 클릭베이트 탐지가 없으면, 시스템은 제목-본문 불일치로 인한 피해를 걸러낼 수단을 잃는다(다른 agent들은 사실관계·확산 측면만 다루고, 제목 과장 자체는 다루지 않기 때문).

```
[기사 입력: 제목+본문]
        │
        ▼
┌─────────────────────────────┐
│  ① 클릭베이트 탐지 Agent     │ ← 본 문서에서 상세 설계 (대회 제출 핵심 범위)
│  ② 검증 Agent (가칭)         │ ← 개념만 정의, 세부 로직은 범위 밖
│  ③ 확산통제 Agent (가칭)     │ ← 개념만 정의, 세부 로직은 범위 밖
└─────────────────────────────┘
        │
        ▼
[조정자(Orchestrator)가 결과 종합]
        │
        ▼
[인간감독 큐 → 검토자 최종 결정]
```

> 이름(②, ③)은 가칭이며 팀 논의로 확정 예정. 예선 단계에서는 대회 권고(1~2개 영향에 집중)에 따라 **①클릭베이트 탐지 Agent만 상세 설계**하고, ②③은 역할 정의 수준에서만 다룬다.

### (2) ① 클릭베이트 탐지 Agent (본 제출물의 핵심 범위)

| 항목 | 내용 |
|---|---|
| 역할 | 뉴스 기사 제목이 본문 내용을 과장·왜곡하는지 판단 |
| 입력 | 뉴스 기사 **제목 + 본문** (텍스트) |
| 출력 | 클릭베이트 여부 판단 · 판단 근거 · 위험도 점수 · 검토 필요 여부 |
| 필수 모델 | [A.X 4.0 Light](https://huggingface.co/skt/A.X-4.0-Light) (SKT, Hugging Face 공개) — 필수 사용, 타 모델 병행 가능 |
| 인간감독 구조 | AI 판단 → **인간감독(검토·승인·보류)** |
| 직접 사용자 | 뉴스 플랫폼 운영팀 — 기사 게시 전 또는 게시 직후 콘텐츠 검토 용도로 사용 |
| Agent 자율범위 | **자율 조치**: 위험도 낮음 → 자동 통과 / **사전 승인 필요**: 클릭베이트 판정 → 검토자 확인 후 게시 보류·경고 표시 / **자동판정 중지(사람에게 이관)**: 정치적으로 민감한 주제, 예측집합이 애매한 경우 |
| 보조 모델 | 현재 단계는 A.X 4.0 Light 단독 운용. 확장 옵션으로 제목-본문 유사도 기반 경량 분류기 추가 검토 |

> **대표 활용 예시**: 대표 시나리오로 **금융·증시 뉴스 도메인**을 든다. 특정 종목(예: 반도체 대형주)의 주가 급락·급등을 자극적으로 과장하거나 근거 없는 공포 심리를 조장하는 기사는, 개인 투자자의 비합리적 매매를 유도하고 해당 기업의 평판·주가에 실질적 영향을 줄 수 있어 클릭베이트의 사회적 위해가 큰 사례로 꼽힌다. 서비스 자체는 도메인을 한정하지 않으며, 이는 어디까지나 설명을 위한 예시임을 명확히 한다.

### (3) ② 검증 Agent (가칭) — 개념 정의만

| 항목 | 내용 |
|---|---|
| 역할 | 기사 내용의 사실관계·출처 신뢰도를 확인. **외부 출처를 검색(RAG)해 사실 확인을 지원** (판단 보조이며 최종 판단은 사람) |
| 입력(예상) | 제목+본문, 검색된 외부 출처 |
| 출력(예상) | 근거 출처 링크를 포함한 사실성 판단 보조 정보 (사실성 점수, 출처 신뢰도) |
| 비고 | 세부 로직·모델 설계는 본 제출 범위 밖. 클릭베이트 탐지와 별개로, "내용 자체가 사실인가"를 다룬다는 점에서 역할 분리 |

### (4) ③ 확산통제 Agent (가칭) — 개념 정의만

| 항목 | 내용 |
|---|---|
| 역할 | ①②에서 위험 판정된 콘텐츠의 확산 범위 제한 방안 결정 (예: 추천 노출 축소, 공유 시 경고 라벨) |
| 입력(예상) | ①②의 판정 결과 |
| 출력(예상) | 조치 유형(노출축소/라벨/차단 등) |
| 비고 | 세부 로직·모델 설계는 본 제출 범위 밖 |

> 아래 2~4번 항목은 전부 **①클릭베이트 탐지 Agent** 기준으로 작성됨 (본 제출물의 상세 설계 범위).

### (5) 서비스 범위의 한계 — 일치성 판단 vs 사실 검증

| 구분 | 내용 |
|---|---|
| ①이 판단하는 것 | **제목이 본문이 뒷받침하는 수준보다 더 단정적이거나 과장되었는지** (제목-본문 일치성) |
| ①이 판단하지 않는 것 | **본문 내용 자체의 사실 여부** (외부 출처·사실관계 확인이 필요해 ② 검증 Agent의 영역) |
| 예시 | 본문에서 "온라인 설문 응답 190명"으로 설명된 수치를 제목이 "190명 처분"처럼 확정 인원으로 단정 → **① 탐지 가능** / 그 설문 결과나 실제 처분 여부가 사실인지 → **① 판단 불가** |
| 문서상 의미 | 본문이 틀렸더라도 제목과 일치하면 ①은 통과시킬 수 있음 → BK02 잔여 위험(RISK-07)로 기록, 사실 확인이 필요한 건은 검토자 외부 출처 확인(BK03 §4-1) 또는 ② 검증 Agent(외부 출처 검색 RAG) 확장으로 연결 |

## 3. 정상/비정상 시나리오

**정상 시나리오**
1. 제목-본문 내용 일치 → "정상" 판정, 낮은 위험도
2. 제목이 본문을 과장/왜곡 → "클릭베이트" 판정 + 근거(불일치 구간) 제시

**비정상/예외 시나리오**
1. 본문 누락 (제목만 존재)
2. 언어 혼재, 특수기호 과다
3. 인용문·풍자 포함 → 오탐 위험 (문맥 점검 필요)
4. 정치·경제적으로 민감한 주제(예: 특정 기업·종목 관련 추측성 보도) → 편향·오탐 위험 및 실질적 파급력 큼
   - 제목이 "설문 응답 수"나 "추정"을 확정 수치·사실처럼 표기한 경우 → 일치성 불일치로 탐지 대상(본문 사실 여부는 판단 안 함)
   - 기사 본문에 모델을 향한 지시문이 포함된 경우(프롬프트 인젝션) → 입력 격리 후 판단, 이상 징후 시 사람에게 이관
5. 검토 대기열 초과 / 검토자 부재 상태에서 판단 요청 발생

## 4. 이해관계자 — Onion Model (직접 → 간접)

> 멘토링 지적: 영향평가의 핵심은 "우리가 보지 못한 것은 없는가"를 넓게 확인하는 것. 직접 사용자뿐 아니라 검토자·개발자·언론사·기업 등 간접 이해관계자까지 포함.

| 층위 | 이해관계자 | 서비스와의 관계 |
|---|---|---|
| 1층 (직접) | 독자 | 기사를 읽고 1차적으로 판단·행동하는 당사자 |
| 1층 (직접) | 검토자(운영팀) | AI 판단을 확인하고 최종 결정을 내리는 사람 |
| 2층 (간접) | 기사 작성자 | AI 판정의 직접 대상이 되는 콘텐츠 제작자 |
| 2층 (간접) | 보도 대상 기업·인물 | 기사 내용의 소재가 되어 평판·주가 등에 영향을 받음 |
| 3층 (간접) | 언론사 전체 | 소속 기자의 기사가 반복적으로 클릭베이트 판정을 받을 경우 매체 신뢰도에 영향 |
| 3층 (간접) | 플랫폼 운영사 | 검수 품질에 따라 플랫폼 신뢰도·법적 책임에 영향 |
| 4층 (사회) | 정보 생태계 전반 | 클릭베이트 탐지 기준 자체가 여론·정보 유통 구조에 영향을 줄 수 있음 |

## 5. 영향 — 다각도 점검 (기대/의도 여부, 기본권 관점)

> 멘토링 지적: 영향을 "기술적으로 잘못됐을 때"로만 좁히지 말 것. 기대/비기대, 의도/비의도, 주된/부수적, 긍정/부정, 그리고 **"서비스가 잘 작동해서 발생하는 역기능"**까지 봐야 함.

| 관점 | 해당 사례 |
|---|---|
| 기대한 영향 | 클릭베이트 기사 노출 감소 → 독자의 정보 소비 품질 향상 |
| 기대하지 않은 영향 | 과도한 민감 판정으로 특정 언론사·필진의 기사가 반복적으로 불리하게 취급됨 |
| 의도하지 않은 영향 | 탐지 기준이 보수적일수록 풍자·은유적 제목의 창작 기사도 함께 걸러질 수 있음 |
| 부수적 영향 | 검토자의 업무 부담 증가(IMPACT-03) |
| 서비스가 "잘 작동해서" 발생하는 역기능 | 탐지 기준을 강화할수록 정상 기사까지 과잉 차단 → 독자의 알 권리·정보 접근 제한 |

**기본권 체크리스트** (헌법상 권리 기준으로 놓친 영향 점검)

| 기본권 | 본 서비스와의 관련성 |
|---|---|
| 알 권리·정보 접근 | 과잉 차단 시 독자가 필요한 정보에 접근하지 못할 위험 (IMPACT-04로 반영) |
| 표현의 자유 | 기사 작성자의 표현이 반복적으로 "클릭베이트"로 분류되어 위축될 위험 |
| 평등과 차별 | 특정 언론사·주제(예: 특정 산업·기업 관련 보도)가 구조적으로 더 자주 판정받는 편향 가능성 |
| 선거·정치 관련 권리 | 정치 기사 오판정이 여론 형성에 영향을 줄 수 있어 BK01에서 별도 트랙(즉시 인간 이관)으로 분리함 |

## 6. 이해관계자·영향 후보 (BK01 권고: 3개 이상 상세 작성)

| ID | 이해관계자 | 영향 경로 | 영향 유형 |
|---|---|---|---|
| IMPACT-01 | 독자(예: 개인 투자자 등 정보 소비자) | 미탐(클릭베이트 놓침) → 잘못된 정보 소비 → 후속 판단·의사결정(예: 매매 결정)에 악영향 | 부정적, 간접 |
| IMPACT-02 | 기사 작성자·대상 기업 | 오탐(정상 기사에 경고) → 언론사 신뢰 손상, 이의제기 부담 / 보도 대상 기업의 평판·주가에 불필요한 영향 | 부정적, 직접 |
| IMPACT-03 | 검토자(운영자) | 경보 과부하 → 판단 피로 → 형식적 승인 증가(즉시승인 패턴 리스크) | 부정적, 직접 |
| IMPACT-04 | 독자(알 권리 관점) | 탐지 기준 과도 강화 → 정상 기사까지 과잉 차단 → 필요한 정보에 접근하지 못함 ("서비스가 잘 작동해서" 발생하는 역기능) | 부정적, 직접 |

> IMPACT-04는 "서비스가 실패해서"가 아니라 "서비스가 의도대로 강하게 작동해서" 발생하는 역기능이라는 점에서 IMPACT-01~03과 성격이 다르며, BK02에서 RISK-01(미탐)과 **상충(trade-off) 관계**로 다룬다 (아래 7번 참고).

## 7. 핵심 트레이드오프 — 무엇을 선택하고 왜 책임지는가

> 멘토링 지적: 위험관리의 핵심은 위험을 "제거"하는 게 아니라 "무엇을 우선하고 그 선택에 어떻게 책임질 것인가"를 결정하는 것.

| 선택지 | 얻는 것 | 잃는 것(새로운 위험) |
|---|---|---|
| 탐지 기준 강화 | 클릭베이트 미탐지(IMPACT-01) 감소 | 정상 기사 오탐·과잉 차단(IMPACT-02, IMPACT-04) 증가 |
| 탐지 기준 완화 | 정상 기사 오탐 감소 | 클릭베이트 미탐지 증가 |

**팀의 선택**: 두 방향 모두 위험이 있으므로, 기준을 중간값으로 두되 **판단 신뢰도가 애매한 구간(기준값 근방)은 전부 사람에게 이관**하는 쪽을 택한다 (BK02 RISK-01 통제, BK03 Trigger 조건 참고). 즉 "AI가 애매하면 틀리지 않고 사람에게 넘긴다"를 원칙으로 책임 소재를 명확히 한다. 이 기준값과 "애매함의 범위"를 정하는 주체는 AI기획자이며, 운영 데이터가 쌓이면 팀 논의로 재조정한다 (BK04 §모니터링 연계).
