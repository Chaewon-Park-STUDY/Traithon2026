## 1. 서비스 정의

| 항목 | 내용 |
|---|---|
| 서비스명 | 클릭베이트 탐지 Agent |
| 입력 | 뉴스/콘텐츠 **제목 + 본문** (텍스트) |
| 출력 | 클릭베이트 여부 판단 · 판단 근거 · 위험도 점수 · 검토 필요 여부 |
| 필수 모델 | [A.X 4.0 Light](https://huggingface.co/skt/A.X-4.0-Light) (SKT, Hugging Face 공개) — 필수 사용, 타 모델 병행 가능 |
| 인간감독 구조 | AI 판단 → **인간감독(검토·승인·보류)** |
| 직접 사용자(잠정) | ⚠️ 팀 확정 필요 — 예: 뉴스 플랫폼 운영팀(게시 전/후 검토), 또는 독자 대상 신뢰도 표시 도구 |

## 2. 사용 데이터

| 구분 | 데이터 | 언어 | 용도 |
|---|---|---|---|
| 메인 | [AI-Hub 낚시성 기사 탐지 데이터](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=71338) | 한국어 | 클릭베이트 탐지, 제목-본문 불일치, 과장·정보 은닉 분석 |
| 보조 | [Webis Clickbait Corpus 2017](https://webis.de/events/clickbait-challenge/shared-task.html) ([다운로드](https://zenodo.org/records/5530410), `clickbait17-train-170630.zip`, 이미지 제외) | 영어 | 클릭베이트 강도, AI-사람 판단 비교, 인간 검토 기준 설정 |

- 두 데이터는 언어·구조가 달라 **목적별로 구분 활용** (단순 병합 지양)
- 정제·가공·증강·주석 추가 가능, 제공 데이터 없이 추가 데이터만 사용 불가
- 추가 데이터 사용 시: 필요 이유 / 기존 데이터 부족한 점 / 보완되는 신뢰성 문제를 설명할 수 있어야 하며, 사전에 멘토·운영팀 확인 권장

## 3. 정상/비정상 시나리오

**정상 시나리오**
1. 제목-본문 내용 일치 → "정상" 판정, 낮은 위험도
2. 제목이 본문을 과장/왜곡 → "클릭베이트" 판정 + 근거(불일치 구간) 제시

**비정상/예외 시나리오**
1. 본문 누락 (제목만 존재)
2. 언어 혼재, 특수기호 과다
3. 인용문·풍자 포함 → 오탐 위험 (문맥 점검 필요)
4. 정치적으로 민감한 주제 → 편향·오탐 위험
5. 검토 대기열 초과 / 검토자 부재 상태에서 판단 요청 발생

## 4. 이해관계자·영향 후보 (BK01 권고: 3개 상세 작성)

| ID | 이해관계자 | 영향 경로 | 영향 유형 |
|---|---|---|---|
| IMPACT-01 | 독자 | 미탐(클릭베이트 놓침) → 잘못된 정보 소비 → 후속 판단·의사결정에 악영향 | 부정적, 간접 |
| IMPACT-02 | 기사 작성자 | 오탐(정상 기사에 경고) → 신뢰 손상, 이의제기 부담 발생 | 부정적, 직접 |
| IMPACT-03 | 검토자(운영자) | 경보 과부하 → 판단 피로 → 형식적 승인 증가(즉시승인 패턴 리스크) | 부정적, 직접 |
