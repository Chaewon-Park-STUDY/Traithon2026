## 1. 초기 아키텍처

```
[뉴스 기사 입력: 제목 + 본문]
        │
        ▼
[전처리: 언어 혼재·본문 누락 등 입력 이상 필터링]
        │
        ▼
[A.X 4.0 Light 판단: 클릭베이트 여부 + 판단 신뢰도]
        │
        ▼
  ┌─────────────┴─────────────┐
  │                           │
정치·경제(특정 기업/종목)    그 외 일반 카테고리
관련 기사                    │
  │                           ▼
  ▼                     [긴급도×중요도 매트릭스로 우선순위 산정]
[무조건 인간 이관]              │
(매트릭스 계산 생략)      ┌─────┼─────┐
  │                    낮음   보통   높음(최우선)
  │                      │     │     │
  ▼                      ▼     ▼     ▼
[검토자 큐]          자동/24h  4h   1h 이내
                       처리   이내   검토
```

## 2. 우선순위 매트릭스 (긴급도 × 중요도)

| | 긴급도 낮음 | 긴급도 높음 |
|---|---|---|
| **중요도 높음** | 4시간 이내 검토 | **1시간 이내 검토 (최우선)** |
| **중요도 낮음** | 자동 처리 / 24시간 이내 후순위 | 간단 확인 후 신속 처리 |

- **긴급도**: 방치 시 확산·피해 확대 속도 (예: 조회수·공유 급증 여부)
- **중요도**: 파급력 크기 (예: 영향받는 독자 수, 경제·사회적 영향 규모)

## 3. 정치·경제 카테고리 — 별도 트랙

정치, 그리고 특정 기업·종목과 관련된 경제 기사는 **매트릭스 점수 계산 없이 무조건 인간에게 즉시 이관**한다.

- **이유**: 위험도 산정의 문제가 아니라, 명예훼손·시장 영향 등 **법적·비즈니스적 민감성** 때문에 애초에 AI 단독 자동판정 대상이 될 수 없는 영역으로 본다.
- Agent는 이 카테고리를 식별하는 역할까지만 수행하고, 판단 자체는 하지 않는다.

## 4. 운영·인간감독(Human Oversight) 설계

Human Oversight는 "사람이 AI 결과를 최종 확인한다"는 한 가지 방식으로 끝나지 않고, 아래와 같이 **전체 운영 프로세스**로 설계한다.

```
AI 판단(클릭베이트 여부+신뢰도)
      ↓
Trigger·Condition (아래 표의 개입 조건 중 하나라도 해당 시 발동)
      ↓
Human Review / Intervention (검토자가 확인)
      ↓
Resulting Action (승인 / 수정 / 보류 / 반려)
      ↓
Record (판단 근거·결과 기록)
      ↓
Feedback / Update (잔여 위험 재검토·기준 업데이트에 반영, BK02 연계)
```

### 4-1. 6가지 설계 질문에 대한 답

| 질문 | 답변 |
|---|---|
| **언제 사람이 반드시 개입해야 하는가** (Trigger) | ① 정치·경제(특정 기업/종목) 카테고리 식별 시 ② 우선순위 매트릭스상 "높음"(1시간 이내) ③ 모델 판단 신뢰도가 일정 기준 미만일 때 ④ 인용문·풍자 등 예외 시나리오로 분류된 경우(BK01 참고) |
| **누가 개입해야 하는가** | 뉴스 플랫폼 운영팀 내 콘텐츠 검토 담당자(검토자) |
| **개입하는 사람에게 어떤 정보가 제공되는가** | 원문(제목+본문), AI 판단 결과(클릭베이트 여부), 판단 신뢰도 수치, 판단 근거(불일치 구간 등), 분류된 트리거 사유 |
| **사람은 어떤 행동을 할 수 있는가** | 승인(그대로 게시) / 경고 표시 후 게시 / 게시 보류 / 반려(수정 요청) |
| **개입 결과는 시스템에 어떻게 반영되는가** | 결정에 따라 기사 상태 업데이트(정상/경고/보류/반려), 반려 시 재제출 절차로 연결 |
| **언제·왜·누가 개입했고 어떤 판단을 내렸는지 어떻게 기록하는가** | 모든 검토 건에 대해 트리거 사유, 검토자, 판단 근거, 최종 결정, 처리 시각을 기록 → BK02 잔여 위험 재검토 시 활용 |

### 4-2. SLA 및 운영 규칙

| 항목 | 내용 |
|---|---|
| SLA | 위 우선순위 매트릭스 기준 (최우선 1시간 / 차순위 4시간 / 일반 24시간) |
| 검토자 부재 시 | 큐에 쌓아두고 최우선 건부터 처리 (RISK-03의 "형식적 즉시승인" 방지를 위해 자동 승인으로 전환하지 않음) |
| 정치·경제 카테고리 처리 | 매트릭스 계산 없이 즉시 Trigger 발동 (3번 항목 참고) |
| 사후 대응과의 관계 | 독자 신고 등 사후 대응만으로는 불충분하다고 보고, **게시 전/판단 진행 중 단계에서 개입**하는 것을 기본으로 함(사후 신고 체계는 보완적으로만 운영) |

## 5. 에이전트 자율범위 및 통제 (Agentic 위험 대응)

본 서비스는 Agent 형태로 동작하므로, 자율 판단·행동에 따른 아래 위험을 함께 통제한다.

| 위험 | 통제 방안 |
|---|---|
| 모델 환각(Hallucination)으로 존재하지 않는 근거 제시 | 판단 근거는 반드시 입력 원문 내 구간을 직접 인용하는 방식으로만 생성(자유 생성 근거 미사용) |
| 지나치게 넓은 자율 권한 | Agent는 "판단 + 근거 제시 + 카테고리 분류"까지만 수행, 게시/반려 등 **실행 행동은 전적으로 사람이 결정**(BK01 자율범위 참고) |
| 잘못된 판단의 연쇄(다음 행동으로 자동 이어짐) | 각 기사 단위로 판단을 종료하고 자동으로 다음 조치(예: 자동 경고 발송 등)로 연결하지 않음 |
| 필요한 시점에 인간 개입 누락 | 4-1의 Trigger 조건을 시스템 레벨에서 강제(조건 충족 시 자동 게시 로직 자체를 차단) |
