# BK04. 통제 및 요구사항

작성일: 2026-10-02 | 팀명: 레드투그린

> 목적: BK02에서 식별한 위험 각각에 대해, 구체적인 **통제(Control)** 와 이를 보장하기 위한 **요구사항(Requirement)** 을 정의하고, BK03 아키텍처의 어느 부분에서 구현되는지 연결한다. (멘토링 3주차 가이드: 위험 → 통제 → 요구사항 → 아키텍처 연결 확인)

---

## 1. 위험별 통제·요구사항 매핑

| 위험 ID | 통제(Control) | 요구사항(Requirement) | 아키텍처 반영 위치 |
|---|---|---|---|
| RISK-01 (클릭베이트 미탐지 → 독자 피해) | 판단 신뢰도가 기준 미만이면 자동 통과 대신 사람에게 이관 | 시스템은 모든 판단에 신뢰도 점수를 함께 출력해야 한다 | BK03 아키텍처 "A.X 4.0 Light 판단" 단계 출력값에 신뢰도 포함 |
| RISK-02 (정상 기사 오탐 → 신뢰·평판 피해) | 오탐 시 이의제기 채널 제공, 판정 근거 상시 공개 | 모든 "클릭베이트" 판정에는 근거(불일치 구간)가 함께 제공되어야 한다 | 검토자 큐 및 최종 게시 화면에 판정 근거 노출 |
| RISK-03 (검토자 경보 과부하 → 형식적 승인) | 우선순위 매트릭스로 검토 큐 정렬, 자동 승인 전환 금지 | 검토자 부재 시에도 큐는 쌓이기만 하고 자동 승인되지 않아야 한다 | BK03 "긴급도×중요도 매트릭스" + 운영 규칙 |
| RISK-04 (정치·경제 민감 주제 편향 판단) | 해당 카테고리는 매트릭스 계산 없이 즉시 인간 이관(자동판정 대상에서 원천 제외) | 정치·경제(특정 기업/종목) 카테고리 식별 로직은 판단 단계보다 먼저 동작해야 한다 | BK03 아키텍처 분기(전처리 직후 카테고리 분기) |
| RISK-05 (입력 이상 케이스 처리 실패) | 입력 전처리 단계에서 사전 필터링, 실패 시 "판단 보류" 반환 | 본문 누락·언어 혼재 등은 AI 판단 이전에 걸러져야 한다 | BK03 "전처리" 단계 |
| 에이전트 환각 위험 (BK03 §5) | 판단 근거는 원문 인용 방식으로만 생성 | 자유 생성 근거(원문에 없는 문장)는 출력에 포함되어서는 안 된다 | A.X 4.0 Light 출력 포맷 제약(근거=원문 구간 인덱스) |
| 에이전트 과도한 자율권한 (BK03 §5) | 실행 행동(게시/반려)은 항상 사람이 결정 | Agent는 판단·분류까지만 수행하고 게시 여부를 자체 실행해서는 안 된다 | BK03 아키텍처 "검토자 큐" 이후 단계는 사람 전담 |

## 2. 공통 요구사항 (전체 시스템 수준)

- **추적성**: 모든 판정·개입·결정은 타임스탬프와 함께 기록되어야 한다 (BK03 §4-1 "기록" 항목과 연결)
- **일관성**: 동일한 입력(제목+본문)에 대해서는 동일한 신뢰도 범위 내 판단을 반복 가능해야 한다 (모델 버전 고정 또는 버전 기록)
- **데이터 사용 원칙 준수**: 메인(AI-Hub)·보조(Webis) 데이터 외 데이터 추가 시 BK01에 명시한 설명(필요성·부족한 점·보완되는 신뢰성 문제) 기록 의무화

## 3. 요소 간 일관성 점검 (멘토링 6번 항목 자가 점검)

| 점검 항목 | 확인 |
|---|---|
| 서비스 개념·목적 ↔ 이해관계자 | BK01의 이해관계자 3개(독자, 작성자·기업, 검토자)가 서비스 정의(뉴스 기사 클릭베이트 탐지)와 직접 연결됨 ✅ |
| 이해관계자 ↔ 영향 | BK01 IMPACT-01~03이 각 이해관계자별로 구체적 피해 경로를 설명함 ✅ |
| 영향 ↔ 위험 | BK02 RISK-01~05가 각 IMPACT에 매핑됨 ✅ |
| 위험 ↔ 통제·요구사항 | 본 문서(BK04) §1에서 매핑 완료 ✅ |
| AI·모델 역할 ↔ 사람의 역할 | BK03 §5에서 Agent는 "판단·분류"까지, 사람은 "실행 결정"을 담당하도록 명확히 분리 ✅ |
| 통제·요구사항 ↔ 아키텍처 | 본 문서(BK04) §1 "아키텍처 반영 위치" 열에서 확인 ✅ |
